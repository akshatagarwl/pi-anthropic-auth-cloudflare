# pi-anthropic-auth-cloudflare

An **unofficial, experimental TypeScript port** of request shaping from
[@gotgenes/pi-anthropic-auth](https://github.com/gotgenes/pi-anthropic-auth)
for **pi-ai 1.2.x** provider collections and pi-durable. GitHub-source distribution
only; no npm release. MIT, with upstream attribution in [NOTICE](NOTICE).

**No live subscription acceptance or billing test has been performed. This
adapter does not guarantee subscription billing, avoid charges, increase limits,
or grant permission to use Claude subscription credentials in third-party apps.**

## Terms and billing: read before enabling

says developers building products/services should use API keys. It explicitly
prohibits third-party Claude.ai login offerings, routing users' Free/Pro/Max
credentials, and collecting/storing/intermediating Claude.ai credentials or
session tokens. Enforcement can occur without notice. See also the
[Consumer Terms](https://www.anthropic.com/legal/consumer-terms) and
[Commercial Terms](https://www.anthropic.com/legal/commercial-terms).

Do not treat this research port as authorization to deploy subscription login.
Obtain Anthropic authorization for your intended use; use API keys otherwise.
Client-identity text and a billing marker cannot override server-side policy or
entitlements. Requests may be rejected, draw on extra usage, or incur charges.
A successful response or usage-token count is **not** proof of plan-limit billing.
The upstream package's claims are not independently verified here.

## What it does

- Wraps **only** the existing `anthropic` provider, locally to one `MutableModels`.
- Shapes requests only for `anthropic-messages` with resolved tokens containing
  `sk-ant-oat`, matching pi-ai's own detection.
- Uses Web Crypto SHA-256 to prepend upstream-compatible billing **system text**.
  This is not an HTTP billing header.
- Sanitizes recognized Pi CLI prompt sections and mid-conversation updates;
  retains custom/project instructions, cache controls, tools, effort-only updates,
  and signed assistant thinking without splitting or reordering assistant turns.
- Composes caller `onPayload` first, shaping last. Preserves API-key options and
  other providers. Leaves auth, login, refresh, catalog, SDK headers, tool naming,
  event parsing, cancellation, and normal SDK retry policy upstream-owned.
- Adds no runtime dependencies, CLI extension loader, Node imports, filesystem
  access, environment-variable reads, global fetch patch, or credential storage.

[Research and exact source citations](docs/research.md).

## Build and test

Node **24** is the tested development environment. A Worker only needs Web APIs.

```sh
cd /Users/akshat/workspace/pi-anthropic-auth-cloudflare
npm ci
npm run check
npm test
npm run build
```

Tests run offline against fake credentials/mocked HTTP; workerd is local. They
cover hashing, payloads, both SDK stream paths, incremental SSE/tools, passthrough,
HTTP/stream failures, cancellation, version alignment, and collection-owned fake
OAuth refresh. Bundle tests assert the adapter has no runtime imports. It runs
in workerd without Node compatibility; a separate real pi-ai SDK workerd probe
uses `nodejs_compat` for upstream dependencies.

## Copy-paste integration (opt-in; not applied to the target app)

After building this checkout, link it into a sibling application:

```sh
cd /Users/akshat/workspace/pi-durable-cf
pnpm add ../pi-anthropic-auth-cloudflare
```

Once this repository is published on GitHub, clone it next to your application
and use the same local-source/build procedure. There is no published GitHub URL
or npm artifact yet. `private: true` deliberately prevents accidental npm publish;
`dist/` is generated by `npm run build` (also the Git install `prepare` script).

For the target's `src/models.ts`, the complete model factory becomes:

```ts
import type { CredentialStore, MutableModels } from "@earendil-works/pi-ai";
import { registerBunOAuthFlows } from "@earendil-works/pi-ai/bun-oauth";
import { builtinModels } from "@earendil-works/pi-ai/providers/all";
import { installAnthropicOAuth } from "pi-anthropic-auth-cloudflare";

// Keep the host's existing static registration for Worker login/refresh bundling.
registerBunOAuthFlows();

export function createAppModels(credentials: CredentialStore): MutableModels {
  const models = builtinModels({ credentials });
  models.deleteProvider("cloudflare-workers-ai");
  // Opt in only after resolving the authentication-policy risks above.
  installAnthropicOAuth(models);
  return models;
}
```

Keep the target's other exports, including `PREFERRED_MODELS`. Its existing
`src/chat.ts:createChatHarnessOptions` already supplies this same collection in
`HarnessOptions.models`; no harness rewrite is needed. For another host, call
`installAnthropicOAuth(models)` once immediately after creating its mutable
collection and before issuing requests. It throws if `anthropic` is absent.
No target files were edited by this repository's implementation.

### API and version handling

```ts
import { installAnthropicOAuth, wrapAnthropicProvider } from "pi-anthropic-auth-cloudflare";
import { anthropicProvider } from "@earendil-works/pi-ai/providers/anthropic";

installAnthropicOAuth(models); // existing collection
// Or construct a provider explicitly instead of installing into a collection:
const decorated = wrapAnthropicProvider(anthropicProvider());
```

`wrapAnthropicProvider` accepts the plain built-in `anthropicProvider()` result
(or a plain-object decorator of it), not arbitrary class-based providers or
other provider IDs. Use either installation style, not both.

Default billing version is upstream 3.4.3's `2.1.280` floor, raised to a newer
`claude-cli/X.Y.Z` wire user-agent. To set an **absolute** billing version:

```ts
installAnthropicOAuth(models, { claudeCodeVersion: "2.1.280" });
```

Only bare `X.Y.Z` is accepted; invalid configuration throws. Explicit pins do not
raise automatically. No `process.env` configuration is read. Existing
caller-supplied billing blocks are preserved, not updated. Empty first-user text
adds no billing block. The adapter never invents a user message to hash.

## Limitations and rollback

- Tested against pi-ai **1.2.0**, peer range **1.2.x**, and the pi-durable 1.2.0
  call seam. Older `@mariozechner/pi-ai` and CLI extension registries are not
  supported. Revalidate upstream payload/version changes before upgrading.
- No upstream learned-version floor, `claude_code_version_too_old` retry, error
  hint rewriting, extra-provider aliases, CLI config, account profiling or
  diagnostics. Version rejection remains an error; review policy/dependencies
  and explicitly configure a version if appropriate. It never proves billing.
- Direct compat API calls, other collections, provider replacements installed
  later, custom SDK `client` instances, and header-only OAuth auth bypass shaping.
  Both `Models.stream` and `Models.streamSimple` (and their completion helpers)
  are covered when they reach the decorated provider.
- Version alignment assumes pi-ai's SDK sends serialized JSON in `fetch`'s
  `init.body`. Request-only streams/custom body forms pass through unread.
  Responses are never read, cloned or rewritten by the adapter.
- Unknown/unstructured prompts pass through conservatively. It is not a generic
  prompt sanitizer. No login/refresh network test, deployed Worker test, full
  target-app test, or real account/billing verification was performed.
- Stop using it by removing the install call and rebuilding/recreating the
  collection. API-key requests remain unshaped even while installed. Review
  account usage separately; never publish access/refresh tokens or raw payloads.
